# ABX

[English](README.md) | **Русский**

ABX (Agent Box) запускает консольных агентов для работы с кодом внутри песочниц Bubblewrap на Linux. Каждый профиль — это постоянный приватный home агента или набора связанных инструментов: исполняемые файлы, настройки, кэши и авторизация сохраняются между запусками.

При запуске агента текущий проект подключается с записью как `/workspace`. Профиль доступен с записью как `/home/agent`; выбранные системные файлы доступны только для чтения; временные каталоги, процессы и устройства имеют отдельные представления внутри песочницы. Сеть общая с хостом. Точные границы описаны в [модели защиты](docs/ru/security.md).

## Требования

- Linux. Готовый опубликованный бинарник предназначен для x86-64 (`amd64`).
- Запускайте ABX обычным пользователем, без `sudo`.
- Bubblewrap **0.12.0 или новее** по пути `/usr/bin/bwrap`; хост должен разрешать непривилегированные user namespaces.
- Локальная запись `/etc/passwd` для вашего UID с корректным домашним каталогом и пригодным login shell.
- Среда выполнения или менеджер пакетов, который нужен выбранному агенту, например Bun или npm.

## Установка

Скачайте бинарный архив и файл контрольных сумм нужной версии:

```text
abx-X.Y.Z-linux-amd64.tar.gz
abx-X.Y.Z-SHA256SUMS
```

Проверьте и установите бинарник:

```sh
abx_version=X.Y.Z
sha256sum --check --ignore-missing "abx-$abx_version-SHA256SUMS"
tar -xzf "abx-$abx_version-linux-amd64.tar.gz"
mkdir -p "$HOME/.local/bin"
install -m 755 "abx-$abx_version-linux-amd64/abx" "$HOME/.local/bin/abx"
export PATH="$HOME/.local/bin:$PATH"
abx version
```

Показанная версия должна совпадать со скачанной. Если `$HOME/.local/bin` ещё не входит в PATH, добавьте его в настройки своей оболочки.

Если хотите собрать ABX самостоятельно, см. [Установку](docs/ru/installation.md#сборка-из-исходников).

## Быстрый старт

Создайте профиль. Имя профиля должно совпадать с исполняемым файлом, который будет запускать `run`:

```sh
abx profile create opencode
abx shell opencode
```

Теперь вы внутри песочницы профиля с `HOME=/home/agent`. Например, установите OpenCode через Bun:

```sh
bun add -g opencode-ai
opencode --version
exit
```

Перейдите во внешнем терминале в каталог проекта и запустите агента:

```sh
cd "$HOME/code/my-project"
abx verify opencode
abx run opencode
```

`verify` необязателен, но полезен после установки или изменений на хосте. Он запускает настоящую тестовую песочницу и проверяет основные свойства изоляции; установленный исполняемый файл агента для этого не нужен.

В одном профиле можно держать [Herdr](https://herdr.dev/) и несколько agent CLI. Для detach/reattach используйте `work`, чтобы после выхода из клиента оставаться в shell той же песочницы.

На хосте создайте профиль и откройте shell для установки:

```sh
abx profile create herdr
abx shell herdr
```

Внутри ABX установите инструменты, затем вернитесь на хост:

```sh
curl -fsSL https://herdr.dev/install.sh | sh
bun add -g opencode-ai
# Pi и другие agent CLI установите их обычным способом.
exit
```

На хосте перейдите в проект и откройте рабочий shell:

```sh
cd "$HOME/code/my-project"
abx work herdr
```

Внутри ABX запустите Herdr:

```sh
herdr
```

ABX подключает проект хоста как `/workspace`. Если Herdr открыл первый workspace в `/home/agent`, создайте workspace проекта явно изнутри ABX:

```sh
herdr workspace create --cwd /workspace --label project --focus
```

После detach снова выполните `herdr` в оставшемся shell. `exit` из этого shell завершает сессию ABX; следующий `abx work` создаёт новую песочницу. Herdr и его агенты используют общий профиль и проект; для разделения состояния или учётных данных используйте отдельные профили.

Для прямого запуска без внешнего shell можно выполнить на хосте `abx run herdr`. Подробнее — [работа в проекте](docs/ru/usage.md#shell-в-проекте-work).

## Команды

| Команда | Назначение |
|---|---|
| `abx profile create <name>` | Создать пустой постоянный профиль |
| `abx profile show <name>` | Показать путь профиля, состояние основного исполняемого файла и shared skills |
| `abx profile list` | Показать список профилей |
| `abx shell <name>` | Открыть login shell профиля без подключения проекта |
| `abx work <name>` | Открыть login shell с текущим проектом в `/workspace`; одноимённый executable не требуется |
| `abx run <name> [-- <argument>...]` | Запустить одноимённый основной исполняемый файл профиля с текущим каталогом как `/workspace` |
| `abx inspect <name>` | Показать план `run` без запуска Bubblewrap; требуется одноимённый executable профиля |
| `abx verify <name>` | Запустить тестовую песочницу и проверить основные свойства изоляции |
| `abx help` | Показать справку CLI |
| `abx version` | Показать версию ABX |

По умолчанию профили находятся в `~/.local/share/abx/profiles`. Абсолютный `XDG_DATA_HOME` меняет базовый каталог хранения. Точный путь профиля можно посмотреть через `abx profile show <name>`.
