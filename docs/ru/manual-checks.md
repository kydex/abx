# Необязательные ручные проверки

[English](../manual-checks.md) | **Русский**

Этот сценарий необязателен: используйте его для разбора проблемы или проверки поведения после существенного для задачи изменения ABX, Bubblewrap или хоста. Его **не нужно выполнять перед каждым релизом**; он не добавляет условий выпуска или проверок CI. Существующие требования к автоматическим и live-тестам не меняются.

Нужен поддерживаемый Linux-хост и обычный пользователь. Разделы 1–2 готовят временные профили; затем выберите нужные разделы 3–6 и завершите очисткой из раздела 7. Каждый выбранный сценарий выполняйте один раз на свежей подготовке. Скачивание агента, авторизация, sudo и изменение mounts хоста не нужны. Пример проверяет небольшой исполняемый файл, а не конкретный менеджер пакетов или агент.

## Как вводить команды

- **Терминал A** — первый терминал; держите его открытым до очистки. В нём чередуются хост и песочница.
- **Терминал B** — второй терминал на хосте, только для TERM/HUP.
- **ОДНА КОМАНДА**: скопируйте только её, нажмите Enter и дождитесь результата. Не объединяйте со следующим блоком.
- **БЛОК**: скопируйте весь блок. В частности, `cat ... <<'SCRIPT'` нужно вставлять полностью, включая завершающую строку `SCRIPT`.
- Не копируйте приглашения и ожидаемый вывод. Не вставляйте весь документ сразу.
- `abx shell`, `abx work`, `exec /bin/sh` и `exit` меняют оболочку или сессию. Ниже они всегда вынесены отдельно.
- Начинать можно из fish. В песочнице снова может открыться fish; перед продолжением перейдите в sh отдельной командой `exec /bin/sh`.

## 1. Подготовка на хосте

**Терминал A · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
sh
```

Дождитесь нового приглашения перед копированием следующего блока.

**Терминал A · хост · БЛОК — вставить целиком**

```sh
PS1='[HOST A] $ '
export PS1
```

Теперь приглашение — `[HOST A] $`. Убедитесь, что `abx` в PATH — нужный бинарник. Не включайте `set -e`: некоторые проверки намеренно возвращают ненулевой код. При неожиданной ошибке остановитесь.

**Терминал A · хост · БЛОК — вставить целиком**

```sh
command -v abx
abx version
/usr/bin/bwrap --version
uname -sr
id -u
umask 077
abx_manual_root=$(mktemp -d /tmp/abx-manual.XXXXXXXX) || exit
export XDG_DATA_HOME="$abx_manual_root/data"
mkdir "$abx_manual_root/project"
cd "$abx_manual_root/project" || exit
printf 'Temporary directory: %s\n' "$abx_manual_root"
abx profile create smoke
abx profile create empty
abx profile show smoke
abx profile list
```

Ожидается: UID не равен нулю; профили `smoke` и `empty` в показанном временном каталоге. `smoke` существует, но команда недоступна. Сохраните показанный путь; все команды хоста в A используют это временное хранилище.

## 2. Установка примера в shell

**Терминал A · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
abx shell smoke
```

Дождитесь нового приглашения перед копированием следующего блока.

**Терминал A · внутри песочницы · ОДНА КОМАНДА — выполнить отдельно**

```sh
pwd
```

Ожидается `/home/agent`. Теперь замените login shell песочницы на sh:

**Терминал A · внутри песочницы · ОДНА КОМАНДА — выполнить отдельно**

```sh
exec /bin/sh
```

Дождитесь нового приглашения перед копированием следующего блока.

**Терминал A · внутри песочницы · БЛОК — вставить целиком**

```sh
PS1='[SANDBOX] $ '
export PS1
```

**Терминал A · внутри песочницы · БЛОК — вставить целиком**

```sh
test ! -e /workspace && printf 'Project hidden\n'
mkdir -p "$HOME/.local/bin"
cat > "$HOME/.local/bin/smoke" <<'SCRIPT'
#!/bin/sh
case "${1-}" in
  wait) exec sleep 600 ;;
  status17) exit 17 ;;
  skills)
    cat /home/agent/.agents/skills/marker || exit 1
    if printf 'unexpected-write\n' >> /home/agent/.agents/skills/marker; then
      printf 'FAIL: skills writable\n'
      exit 1
    fi
    exit 0
    ;;
esac
printf 'cwd=%s\nhome=%s\nsecret=%s\n' "$(pwd)" "$HOME" "${ABX_MANUAL_SECRET-unset}"
printf 'argc=%s\n' "$#"
for arg do printf 'arg=<%s>\n' "$arg"; done
SCRIPT
chmod 700 "$HOME/.local/bin/smoke"
```

Ожидается `Project hidden`. Небольшой скрипт установлен во временный профиль. Вернитесь на хост:

**Терминал A · внутри песочницы · ОДНА КОМАНДА — выполнить отдельно**

```sh
exit
```

Дождитесь нового приглашения перед копированием следующего блока.

**Терминал A · хост · БЛОК — вставить целиком**

```sh
pwd
printf 'storage=%s\n' "$XDG_DATA_HOME"
command -v abx
```

Ожидается: временный каталог `project`, хранилище в соседнем `data` и путь к ABX на хосте. Так вы подтверждаете, что вернулись на хост.

## 3. Аргументы, окружение и коды завершения

**Терминал A · хост · БЛОК — вставить целиком**

```sh
abx profile show smoke
abx inspect smoke
env ABX_MANUAL_SECRET=hidden abx run smoke -- 'a b' '$(literal)' ''
abx run smoke -- status17
printf 'exit=%s\n' "$?"
abx run smoke unexpected
printf 'exit=%s\n' "$?"
abx profile create smoke
printf 'exit=%s\n' "$?"
(cd / && abx run smoke)
printf 'exit=%s\n' "$?"
```

Ожидается: show показывает исполняемый файл; inspect описывает `/workspace`, профиль и очищенное окружение. Run выводит `cwd=/workspace`, `home=/home/agent`, `secret=unset`, `argc=3`; аргументы — `a b`, `$(literal)` и пустая строка. Четыре кода завершения — `17`, `2`, `1`, `1`: код дочернего процесса, синтаксис CLI, существующий профиль, запрещённый проект. Сообщения этих намеренных ошибок ожидаемы.

## 4. Work, сохранение данных и фоновая запись

**Терминал A · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
abx work empty
```

Дождитесь нового приглашения перед копированием следующего блока.

**Терминал A · внутри песочницы · ОДНА КОМАНДА — выполнить отдельно**

```sh
pwd
```

Ожидается `/workspace`, хотя исполняемый файл `empty` не установлен.

**Терминал A · внутри песочницы · ОДНА КОМАНДА — выполнить отдельно**

```sh
exec /bin/sh
```

Дождитесь нового приглашения перед копированием следующего блока.

**Терминал A · внутри песочницы · БЛОК — вставить целиком**

```sh
PS1='[SANDBOX] $ '
export PS1
```

**Терминал A · внутри песочницы · БЛОК — вставить целиком**

```sh
printf 'persistent\n' > /home/agent/keep
printf 'private\n' > /tmp/abx-manual-private
nohup /bin/sh -c 'while :; do printf x >> /workspace/heartbeat; sleep 1; done' </dev/null >/tmp/abx-heartbeat.log 2>&1 &
sleep 3
wc -c /workspace/heartbeat
```

Ожидается число байтов больше нуля.

**Терминал A · внутри песочницы · ОДНА КОМАНДА — выполнить отдельно**

```sh
exit
```

Дождитесь нового приглашения перед копированием следующего блока.

**Терминал A · хост · БЛОК — вставить целиком**

```sh
sleep 2
wc -c heartbeat
sleep 3
wc -c heartbeat
```

Два числа на хосте должны совпасть: фоновая запись остановилась. Если они растут, остановитесь и разберите причину до очистки. Стабильный размер подтверждает поведение этого примера, а не любых возможных потомков. Теперь откройте новую сессию:

**Терминал A · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
abx work empty
```

Дождитесь нового приглашения перед копированием следующего блока.

**Терминал A · внутри песочницы · ОДНА КОМАНДА — выполнить отдельно**

```sh
exec /bin/sh
```

Дождитесь нового приглашения перед копированием следующего блока.

**Терминал A · внутри песочницы · БЛОК — вставить целиком**

```sh
PS1='[SANDBOX] $ '
export PS1
```

**Терминал A · внутри песочницы · БЛОК — вставить целиком**

```sh
cat /home/agent/keep
test ! -e /tmp/abx-manual-private && printf 'Fresh tmp\n'
```

Ожидается `persistent` и `Fresh tmp`. Данные профиля сохранились; временная файловая система новая.

**Терминал A · внутри песочницы · ОДНА КОМАНДА — выполнить отдельно**

```sh
exit
```

Дождитесь нового приглашения перед копированием следующего блока.

## 5. Сигналы

### 5.1 Ctrl+C

**Терминал A · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
abx run smoke -- wait
```

Команда ждёт без вывода. Через пару секунд нажмите **Ctrl+C один раз**. Когда вернётся приглашение хоста, сразу выполните:

**Терминал A · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
printf 'exit=%s\n' "$?"
```

Ожидается `exit=130`. Между возвратом и чтением `$?` не вводите другие команды.

### 5.2 TERM

**Терминал A · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
sh -c 'printf "ABX PID: %s\n" "$$"; exec abx run smoke -- wait'
```

Скопируйте выведенный PID. Оставьте A ждать. Откройте терминал B на хосте; запустите отдельный sh, даже если обычная оболочка — fish:

**Терминал B · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
sh
```

Дождитесь нового приглашения перед копированием следующего блока.

**Терминал B · хост · БЛОК — вставить целиком**

```sh
PS1='[HOST B] $ '
export PS1
```

**Терминал B · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
read -r abx_manual_pid
```

Эта команда ждёт ввода. **Вставьте только число PID из A и нажмите Enter.** Дождитесь `[HOST B] $`. Затем проверьте процесс:

**Терминал B · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
ps -p "$abx_manual_pid" -o pid=,args=
```

Продолжайте только если это ожидающий `abx run smoke -- wait` из A. Если процесс уже завершился, запустите его заново и введите новый PID.

**Терминал B · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
kill -TERM "$abx_manual_pid"
```

В **A** дождитесь приглашения хоста, затем сразу выполните:

**Терминал A · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
printf 'exit=%s\n' "$?"
```

Ожидается `exit=143`.

### 5.3 HUP

**Терминал A · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
sh -c 'printf "ABX PID: %s\n" "$$"; exec abx run smoke -- wait'
```

A выводит **новый PID** и ждёт. В B введите это новое число:

**Терминал B · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
read -r abx_manual_pid
```

Вставьте только новый PID и нажмите Enter. После возвращения приглашения B:

**Терминал B · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
ps -p "$abx_manual_pid" -o pid=,args=
```

Убедитесь, что это новый ожидающий процесс из A, затем:

**Терминал B · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
kill -HUP "$abx_manual_pid"
```

В **A**, после возвращения приглашения, сразу выполните:

**Терминал A · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
printf 'exit=%s\n' "$?"
```

Ожидается `exit=129`. Каждый сигнал должен быстро завершать этот пример. Если этого не произошло, зафиксируйте проблему; истечение 600 секунд ожидания не считается успехом. Не используйте PID после завершения процесса. Закройте отдельный shell в B:

**Терминал B · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
exit
```

Дождитесь нового приглашения перед копированием следующего блока.

В B больше ничего выполнять не нужно. Продолжайте в A на хосте.

## 6. Verify и shared skills

**Терминал A · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
abx verify smoke
```

Ожидается финальное сообщение об успехе и `N/A` для shared skills. Затем настройте skills:

**Терминал A · хост · БЛОК — вставить целиком**

```sh
abx_manual_skills="$XDG_DATA_HOME/abx/shared/agents/skills"
mkdir -p "$abx_manual_skills"
chmod 700 "$XDG_DATA_HOME/abx/shared"
printf 'shared-marker\n' > "$abx_manual_skills/marker"
env LC_ALL=C abx run smoke -- skills
cat "$abx_manual_skills/marker"
```

Ожидается: попытка записи выдаёт `Read-only file system`. Последний `cat` на хосте выводит только `shared-marker`, без `unexpected-write`. Затем:

**Терминал A · хост · БЛОК — вставить целиком**

```sh
abx verify smoke
find . "$XDG_DATA_HOME/abx/profiles" -name '.abx-*' -print
```

Ожидается успешный verify, включая `PASS` для mount skills. Последний `find` ничего не выводит. Verify также создаёт временный sentinel в home из passwd; обычное завершение удаляет его, но прерывание может оставить файл. Здесь проверяется обычный mount skills, а не вложенные mounts; см. [границы проверки](security.md#проверка-через-verify).

## 7. Результаты и очистка

Для выбранных сценариев запишите фактические результаты и неожиданный вывод, версии ABX/Bubblewrap и сведения о хосте. Не отмечайте пропущенные проверки как успешные. Сохраните нужные данные вне временного каталога. Выйдите из всех тестовых песочниц; если фоновый процесс остался, остановите именно его до удаления файлов.

**Терминал A · хост · БЛОК — вставить целиком**

```sh
pwd
printf 'temporary=%s\nstorage=%s\n' "$abx_manual_root" "$XDG_DATA_HOME"
```

Проверьте, что временный путь совпадает с разделом 1, а хранилище — его подкаталог `data`. Если нет, ничего не удаляйте. Если всё совпало, вставьте блок очистки:

**Терминал A · хост · БЛОК — вставить целиком**

```sh
cd / || exit
case "$abx_manual_root" in
  /tmp/abx-manual.?*) rm -r -- "$abx_manual_root" ;;
  *) printf 'Unexpected temporary path; not removed\n' ;;
esac
```

Если удаление завершилось без ошибок, закройте отдельный shell хоста отдельной командой:

**Терминал A · хост · ОДНА КОМАНДА — выполнить отдельно**

```sh
exit
```

Дождитесь нового приглашения перед копированием следующего блока.

Вы вернулись в исходную оболочку, в том числе fish, если начинали в ней. Удалён только временный каталог.

## Если вы запутались в оболочках

Перестаньте копировать следующие шаги. По одному приглашению `sh-…$` нельзя определить, на хосте ли вы. Выполните эти команды чтения в текущем терминале:

**Текущий терминал · БЛОК — вставить целиком**

```sh
pwd
printf 'home=%s\nstorage=%s\n' "$HOME" "$XDG_DATA_HOME"
command -v abx
```

В этой песочнице HOME равен `/home/agent`, хранилище — `/home/agent/.local/share`, а хостовый бинарник ABX обычно недоступен. В подготовленном shell хоста A хранилище имеет вид `/tmp/abx-manual.…/data`. Если вы ещё в песочнице, введите `exit` **отдельно**, дождитесь приглашения и проверьте снова. Не создавайте профили и не переназначайте переменные хранилища, пока не определили shell хоста. После `exec /bin/sh` не считайте команды, вставленные вслед за ним, выполненными: нужный следующий блок копируйте заново только после проверки состояния.
