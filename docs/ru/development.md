# Разработка

[English](../development.md) | **Русский**

Этот документ предназначен для разработчиков. Для обычного использования ABX эти команды не нужны.

## Сборка и тесты

Используйте Linux и версию Go, указанную в `go.mod`.

Быстрые тесты:

```sh
make test
```

Локальная статическая сборка:

```sh
make build
./abx version
```

Полный набор локальных проверок:

```sh
make check
```

Для `make check` команды `shellcheck`, `actionlint`, `govulncheck` и `golangci-lint` должны быть доступны в PATH. Сейчас проверка включает:

- `golangci-lint fmt` и `golangci-lint run` для Go-пакетов (форматирование gofumpt/goimports, vet, staticcheck, gosec, errcheck, ineffassign, unused);
- ShellCheck для `scripts/*.sh`;
- `actionlint` для GitHub Actions workflows;
- `govulncheck`;
- проверку статической production-сборки;
- Go-тесты с race detector без кэша и общим coverage floor из `Makefile`;
- независимый прогон `go vet` в дополнение к проверке govet внутри golangci.

Проверка пробелов в незакоммиченных изменениях — локальное удобство, а не гейт: `make local-diff-check` запускает `git diff --check` по требованию. Она исключена из `make check`, потому что на свежем чекауте CI нет ни staged, ни изменённых файлов и находить ей там нечего.

Race detector требует поддерживаемую Go-платформу и рабочий C toolchain. Во время обычной разработки `make test` быстрее.

### Мутационный свип

`scripts/mutation-sweep.py` — не гейт, его не запускает ничто в `make check`. Он глушит каждую проверку `if <условие> {` в защищающих файлах и гоняет тесты этого пакета. Условие превращается в `false && (<условие>)`, а не в голое `false`, чтобы компилятор по-прежнему видел все переменные: подстановка целой строки давала «declared and not used» на проверках, которые прекрасно измеряются, и они попадали в неприменимые, не будучи такими. Компилируется ли пакет, решается отдельной компиляцией, а не поиском слов ошибки в выводе тестов: сообщение теста со словом, которое встречается и в диагностике компилятора, превращало убийство в тихое «неприменимо». Проверка, удаление которой никто не заметит, попадает в выжившие — то есть её можно убрать, и ничего не сломается.

Скрипт **не пишет в ваш репозиторий**. Он выгружает `HEAD` во временный каталог, где нет `.git`, и переписывает файлы там, поэтому убитый запуск не оставит исходник изменённым и ничего не придётся восстанавливать. Если в рабочем дереве есть незакоммиченные изменения, скрипт скажет об этом и измерит `HEAD`, а не их.

Полный прогон заново выполняет весь набор тестов пакета на каждую проверку, поэтому один пакет идёт долго, а остальные быстро; пакеты идут параллельно, потому что тесты пакета видят все его файлы и два файла одного пакета нельзя переписывать одновременно:

```sh
scripts/mutation-sweep.py
```

Имена файлов сужают прогон до минуты-двух — этого достаточно, чтобы убедиться, что сам свип работает как прежде:

```sh
scripts/mutation-sweep.py internal/host/account.go
```

Прежде чем верить числам, прочитайте отчёт о пропусках, который скрипт печатает. Пропущенный тест не падает, поэтому проверка, у которой единственный тест пропускается, выглядит ровно как непокрытая. Это не гипотеза: пока требование о принадлежности `/etc/passwd` root существовало, тесты resolve пропускались в любом контейнере, и проверки под ними считались непокрытыми, хотя CI и обычный хост их выполняли. Скрипт печатает число и имена, чтобы список выживших никогда не выдавался за свойство кода, а не машины.

Два различия, от которых зависит разбор результата. Сбой сборки или vet — это **неприменимо**, а не убийство: такую проверку так отключить нельзя. И разбор идёт по тексту вывода, а не по коду возврата, потому что `go test` возвращает ненулевое и при сбое сборки, и при падении теста. Одно слово в сообщении теста меняет измерение: `unreachable` совпадает с признаком сбоя сборки.

## Live-тесты песочницы

На Linux-хосте от обычного пользователя с Bubblewrap 0.12.0+ по пути `/usr/bin/bwrap` и работающими непривилегированными user namespaces. CachyOS — тот дистрибутив, на котором живые тесты действительно исполняются; `ubuntu-latest` — базовая линия CI, которая их выполнить не может. Хост, близкий к CachyOS, — тот, которому стоит доверять, когда менялись изоляция или время жизни процессов:

```sh
make live
```

Эквивалент:

```sh
env ABX_LIVE=1 go test -count=1 ./...
```

Live tests запускают настоящие сессии Bubblewrap и проверяют runtime-поведение, которое обычные unit tests не могут доказать. Запуск тестов от root не заменяет live-run от обычного пользователя. Юнит-тесты также скипаются по UID: root-only и non-root-only кейсы никогда не выполняются вместе, поэтому ни одна машина не прогоняет полный набор; CI работает от non-root.

Для одного сценария:

```sh
env ABX_LIVE=1 go test -count=1 -v ./internal/app -run '^TestLiveVerify$'
```

Live tests нужны после изменений mounts, namespaces, retained descriptors, project/profile path policy, Bubblewrap translation/execution или verify.

Для диагностики с временными профилями при необходимости используйте [необязательные ручные проверки](manual-checks.md). Они не нужны перед каждым релизом и не заменяют описанные выше автоматические или live-тесты.

## Правила разработки

- Начинайте с ожидаемого пользовательского поведения и его security boundary.
- Оставляйте решение в пакете-владельце: CLI syntax в `cli`, eligibility host-объектов в `host`, sandbox policy в `sandbox`, execution в `bwrap`.
- Сохраняйте явное владение ресурсами и обработку ошибок.
- Не ослабляйте path/FD checks только ради хоста, на котором отсутствует требуемая Linux-функциональность.
- Добавляйте regression tests для существенных failure modes и invariants, а не копию каждой детали реализации.
- Синхронно обновляйте `README.md` / `README.ru.md` и каждую пару английского/русского руководства.
- `CHANGELOG.md` ведите на английском.

## Шероховатости, которые мы принимаем

Это было найдено, взвешено и оставлено как есть. Записано, чтобы никто не
начинал тот же разговор с нуля.

- `Plan.Validate()` остаётся одной длинной функцией. Она стоит между собранным
  планом и аргументами Bubblewrap; её разбиение рискует этой границей ради
  читаемости.
- Девять идентификаторов экспортированы, хотя используются только в своём
  пакете. Снятие экспорта заставит компилятор перестать ловить опечатки в именах
  между пакетами — без выгоды здесь.
- Фаззеры в `internal/probe` собираются и проходят проверки, но никогда не
  фаззятся в CI. Они фиксируют форму входа; запуск по расписанию — отдельное
  решение.
- Оркестратор в `internal/app` сознательно покрыт не полностью. Код там, где его
  проверяли, корректен; закрывать пробел нужно швами для тестов, которые правила
  проекта не приветствуют. Мутационный свип измерял размер пробела: одна
  мутация из одиннадцати в оркестраторе ловится.
- Агрегатный порог покрытия — 74,0% при фактических 90,8%, а `internal/app` — 264 оператора из
  311, которые покрывает его собственный профиль (84,9%). Уполовинив покрытие этого пакета, агрегат
  остаётся на 82,5%, и ворота молчат; ловят они только обнуление, при котором агрегат падает до
  74,2% — едва выше порога. Агрегат ловит грубые регрессии и ничего тоньше. Падение покрытия при зелёных тестах означает, что тесты удалены или пропущены, и вот
  на пропуски стоит смотреть в первую очередь.
  `host.ResolveAccount` — единственная функция этого пакета, до которой не доходит ни один тест:
  это одна строка над `resolveAccount(os.Getuid(), `user.LookupId)`, и добраться до неё можно
  только с настоящей учётной записью хоста. Шов под ней есть и покрыт; на саму обёртку шов не
  заводим.
- `profile list` останавливается на первом профиле с небезопасной раскладкой,
  вместо того чтобы перечислить остальные. Описано в [Использовании](usage.md),
  а не исправлено.
